# 사실 추출·저장 계약

MCP_memorizer는 **답변 작성 중 모델이 호출하는 임의 저장 도구를 제공하지 않는다.** 검색은 read-only MCP 도구로 제공하고, 추출과 저장은 **호스트가 최종 답변을 확정한 뒤** 라이브러리 생명주기로 호출한다.

## 추출 입력과 모델 계약

호스트가 준비하는 필드는 `user_text`, `previous_assistant_message`, `final_answer`, `successful_tool_results`다. 별도 모델 추출 요청에서는 정확히 아래 JSON 모양을 기대한다.

```json
{"facts": ["사용자가 직접 말하거나 허용된 근거로 확인된 재사용 가능한 사실"]}
```

- 사용자 최신 원문이 우선 근거다.
- 직전 Assistant 메시지는 최신 사용자 메시지가 **같은 주제에서 명시 또는 포괄 승인한 경우**에 한해 근거가 될 수 있다.
- 최신 사용자 메시지 뒤에 생성된 `final_answer`를 사용자가 승인했다고 해석하지 않는다.
- 성공한 **비기억조회 도구 결과**는 사용자와 관련된 사실을 입증할 때 근거가 될 수 있다.
- 이미 저장된 기억 검색 결과는 다시 추출 근거로 넣지 않는다. 기억 조회 자체가 새로운 사실 생성 근거가 아니다.
- 질문·호출 지시·검색 요청 자체는 Facts가 아니다. 빈 Facts 목록은 정상적인 결과일 수 있다.
- 사실은 자체적으로 이해 가능한 형태를 유지하되, 원문보다 강한 의미를 창작하지 않는다.

정확한 시스템 프롬프트의 단일 원본은 `mcp_memorizer/extraction/prompt.py`다. 이 문서는 해당 프롬프트를 대신하는 별도의 정책 소스가 아니다.

## 영구 저장 과정

`MemoryRuntime`은 사용자 기준점 확보, 원문 Evidence 기록 및 `extract_facts`/ `finish_turn`을 담당한다.

1. 추출기 결과의 공백/형식 및 빈 문자열을 검증한다.
2. Fact 문자열을 정규화하고 동일 문자열의 중복을 제거한다.
3. 사용자 소유 Fact 노드를 만들거나 기존 동일 항목을 사용한다.
4. 사용자 Anchor에서 Fact로 `asserted_fact` 관계를 추가한다.
5. [Sentence_Breaker 연동](sentence-breaker.md)으로 Concept를 만들고 `mentions` 관계와 검색 색인을 갱신한다.

`record_raw_user_evidence`가 원문 Evidence를 별도로 저장한다. 이 기록만으로 개별 Fact에서 원문으로 완전히 역추적되는 것은 아니다.

## 호스트 책임

- 최종 응답이 확정됐는지 확인하고 추출을 언제 수행할지 결정
- 인증한 계정의 고정된 메모리 사용자 식별자 전달
- 성공한 도구 결과와 기억 검색 결과 구분
- 답변 검증·비동기 실행·사용자별 작업 순서 및 서버 종료 처리

특히 MAI에서 저장이 비동기적으로 실행되는 점은 **MAI 구현 정책**이며, MCP_memorizer가 모든 호스트에 대해 동일한 스케줄러·영속 큐를 제공한다는 뜻이 아니다. 재시작 시 정확히 한 번 저장하는 보장은 현재 개발 알파의 계약이 아니다.

## 실패 의미

잘못된 JSON, 비어 있는 사실 문자열, 저장 예외는 성공으로 위장하지 않는다. 호스트마다 실패 기록·사용자 원문 보존 범위는 다를 수 있으므로 별도로 문서화해야 한다.
